# kOSMos: agent notes

Follows the portfolio standard: https://github.com/jibes/apps-data/blob/main/STANDARD.md
List deviations from it here, each with a reason.

## Stack

- TypeScript strict, React 19, Vite, MapLibre GL JS 6, vite-plugin-pwa, Vitest, Playwright, Capacitor 8 (Android). Node: see `.nvmrc`.
- Check library APIs against the installed types in `node_modules`, not from memory. MapLibre 6 has no default export: `import * as maplibregl`.

## Product rules (MECE)

Five jobs, one control each: **view** (the map), **find** (search), **locate** (location button), **inspect** (tap a label / long-press → place card with share + route; the route card is part of inspect), **go** (Start on the route card → turn-by-turn). A new feature must fit one of them or argue for a sixth. No settings screen: theme follows the system (while navigating it follows the sun instead: light by day, dark after sunset and in tunnels; driving or cycling in the Android app, also where the light sensor finds it dark), language follows the browser.

## Architecture

- `src/core/` is pure logic with no DOM, and every module has tests in `tests/`. The whole map look is `core/palette.ts` (colours) + `core/style.ts` (layers, OpenMapTiles schema). Colours never appear in the style directly; a test enforces it.
- `src/ui/` holds components and map glue (`useMap`, markers, gestures) and may import from `core/`, never the other way round.
- Map labels use self-hosted Inter through the style's `font-faces`, registered under the glyph server's font names (`FONT` in `core/style.ts`) so other scripts fall back to the same weight.
- MapLibre's worker is bundled with `?url` and set via `setWorkerUrl` (`ui/useMap.ts`); without it the worker 404s after bundling.
- Compass: `core/compass.ts` (pure: heading from orientation events, tilt-aware: the top of the screen lying flat, the back held upright, since alpha alone is up to 90° off upright; `filterHeading` smooths by time, not per reading (phones send 10–60 a second): heavily damped held still, quick through a real turn, a one-euro filter on the circle; course vs compass by speed) and `ui/useCompass.ts` (streams headings to subscribers, not React state; phones read magnetic north, so each reading adds the declination at the last fix, `core/magnetic.ts`: WMM2025, pure, tested against NOAA's values; the GPS course is true north already). The location button cycles off → follow → compass (`Follow` in `ui/Controls.tsx`).
- Category search: `core/categories.ts` (pure: the kinds of place are `core/categoryTable.ts`, each with its OpenMapTiles `poi` subclasses and hand-written words in en/de; iD's preset words per subclass are generated into `core/placeWords.ts` by `npm run words`, rerun after changing a kind's values (a test checks); a subclass in a group and a kind of its own gives its preset words to the own kind, and a word one kind names by hand stays its; `fold` ignores case, accents and ß/ss; stations, tram and bus stops are kinds too, and `stops` all of them at once (Haltestelle, ÖPNV), and their rows and dots carry `stop` so their cards show departures; `categoriesFor` suggests at most two, the word as typed before its plural, then beginnings; `misspeltFor` guesses one kind from a slip (1 edit from 6 letters, 2 from 10) only when nothing matches as typed, and its row comes after the Photon names, since Enter takes the top row; nearest first) and `ui/categorySearch.ts`, which fetches and decodes the zoom-14 tiles of the view itself (`core/tiles.ts`; only zoom 14 holds every place, the map's own lower-zoom tiles keep only important ones; at most 48 tiles, nearest the centre, each read once; a new category from a view wider than zoom 12 zooms in once; searching an area again never moves the map; with none in view, the tiles under the view's edges, then up to 64 more around it, 16 at a time nearest first until some hold one: the 5 nearest, `beyond` and said so above them); no search server. Chains: `sharedName` groups the names in view the text begins (spaces, case and accents ignored), a row with the count from 2 places, searched like a kind (`Kind` is a category or `name:<name>`); names are read as typed from zoom 13 only, and Photon's rows wait up to 1 s for them, so the row never pushes the list under a finger; Photon rows within 150 m of a counted branch are left out (`without`). Suggestions are rows above the Photon names, taken by tap or Enter; choosing one closes the list (the input blurs) for `ui/ResultsSheet.tsx`, the places by distance (from `useCategory().results`), a strip at first on phones, open in the side layout, kept hidden under a place card so it comes back as it was, the place opened last (from a row or a dot) marked; a row held, hovered or focused lights its dot (`highlight`: feature-state `hot` on the `search` source, ids in the list's order, reset with new results); editing the text leaves the category. Enter on several names without a row chosen (arrows or hover set one) shows them all as a `found:<text>` kind: Photon's places handed to the map, nearest first, the view fitted to the best and those within 30 km (`nearBest`); one name opens it. Every place row (names, results, recent places) starts with an icon for what it is (`core/placeKind.ts`, pure: Photon's OSM key and value or the tiles' `poi` subclass → train, tram, bus, café, shop, town, street, address… else a pin; kept with a recent place). Results are dots and names in the style's `search` source, above labels and tappable; `ui/useCategory.ts` owns them, "show all" (Enter) and the "Search this area" offer after the user's own pan or zoom (40 % of a view or a zoom step; told by how a move ends: a gesture's own event, or `ASKED` as event data on the location button's flight; the app's other moves, following the position or show all, re-anchor the results unless the offer is already up; with the offer up the search key searches here, as the offer does; a fit to results (`onFit`) stops following, and the location button, while following but the map elsewhere, first flies back to the user (`offCentre`)); they hide while a route is open. Nameless toilets, ATMs, car parks, playgrounds, post boxes, drinking water, recycling, charging points and taxi ranks count (`UNNAMED`, called by their kind). Distances count from the user when in view, else from the middle of the map beside the panel (the side layout's map starts at the panel); each tile read gives up after 8 s. An empty field lists the recent searches (`core/recent.ts`, pure: 8, 30 days, one per place or kind; `ui/useRecent.ts` keeps them in `kosmos.recent.v1`, shared by both fields, the route's own taking places only; only names Photon found are kept, never a map dot), then `COMMON` kinds; nothing is preselected, Delete or the cross forgets one. The place card's Nearby centres the map there, clears and focuses the search (in the tap, so a phone opens its keyboard), and distances count from that place while in view (`near` in `App.tsx`, until locate). The search's text and category live in App (`useSearch` in `ui/SearchBar.tsx`), so they outlive a route; choosing a route's start or destination is its own name-only bar. Photon is asked for 15 names (the list scrolls; a finger pulling it down from its top, 64 px or a flick, blurs the field: list and keyboard away, the text kept, back on focus); a query that is only the word for a kind the tiles do not list (airports: Flughafen, airport…) asks for that OSM tag alone (`worldKind` in `core/search.ts`). Map taps are `ui/useMapTaps.ts`: a label's details come from the nearest Photon hit of its name within a radius by kind of label (150 m for places), else a reverse lookup of its spot's address and no OSM id.
- Opening hours: `core/hours.ts` (pure: the common `opening_hours` subset; anything else is shown as written, never guessed: holidays or closing days alone, too) and `ui/PlaceDetails.tsx`; open or closed now only for places on about the device's clock (`nearDeviceClock`), elsewhere just the week.
- Lanes: `core/lanes.ts` (pure: Valhalla `turn_lanes` per maneuver, shown only when some lanes lead the right way and some do not; size by distance and speed). Comes with the same route request.
- Navigation theme: `core/daylight.ts` (pure: sun elevation, tunnel match against `brunnel=tunnel` lines) and `ui/useNavTheme.ts`, which reads tunnels from the tiles already loaded every few seconds (Valhalla's native response has no tunnel flag); dark holds in a tunnel until a fix outside (GPS often stops there), and each drive starts undecided. In the Android app, driving or cycling only (on foot the phone lives in pockets), the ambient light sensor adds dark: `core/ambient.ts` (pure: dark after 8 s below 10 lux, back after 5 s above 150 lux, at least 30 s between switches; it never makes night or a tunnel light) fed by `watchLight` (`KosmosPlugin.light`, a reading a second, only while the app is in front). While navigating it decides both ways (`data-theme` on `<html>`): the system's dark media query yields to `data-theme='light'`, and `styles/base.css` repeats the dark tokens under `data-theme='dark'`.
- Public transport guidance is `core/ride.ts` (pure, replay-tested like `nav.ts`): walk → wait → ride → arrived from fixes and time; GPS when a fix is fresh, the timetable's arrival times underground. `ui/useRide.ts` also ticks every 3 s so it moves on without fixes; `ui/RideView.tsx` renders it; its banner opens the whole trip (`TransitLegs`, every leg closed at first; a ride's times in one column with boarding and getting off on its progress line, passed stops dimmed). A missed departure (still walking once the vehicle has left; on board only when the position moves along its line; a ride entered on the timetable alone, without a fix, is provisional until the next fix) or a cancelled trip offers a new connection (one request, user-initiated, from the stop when the fix is old; the followed connection stays until it comes); a late vehicle keeps the ride going while the position is on its line. A ride ends at its stop (within the fix's accuracy, at least 40 m), never at the one before; arrival is said only on a position at the destination, never on the timetable alone. What changes is said once each: missed, cancelled, a new platform, a delay of 3 min or more.
- Route drawing, the fit and the start marker are `ui/useRouteLayer.ts`, so `App.tsx` stays the wiring. The route card's swap button exchanges its ends (`onSwap`); "My location" as a destination is the fix then, marked `Place.here`, and swapped back becomes `from: null`, the live position, again.
- Guidance views: `core/navView.ts` (pure: pitch and zoom per way of travel, car 55° by speed, bike 30°, foot from above; what is left of a route or trip) and `ui/useNavView.ts` (following close, `overview`, or neither after a gesture; each trip starts close). One control, `ViewToggle` in `ui/NavBar.tsx`: Overview (the rest of the way, north up, `fitNav`) while following, else Re-centre. Public transport's camera is `ui/useRideCamera.ts`: the dot while walking or waiting, on board the rest of the line to the stop to get off, the overview the rest of the trip. The ride's opened stops are a progress line (`data-passed`, `data-next`). Map gestures and the user's dot are `ui/useMapGestures.ts`.
- Where a way leads: `core/roundabout.ts` (pure, `narrateWays`) prefers the signs over a road's name or number, which run both ways. Any maneuver but leaving, arriving and coming off a roundabout with a signed destination (`Maneuver.toward`, Valhalla's `sign.exit_toward_elements`) gets it as `wayOut` ("towards Tullamore"), added to its instruction, alert and pre prompts unless the router said it already; a roundabout also takes its exit's signs, and without any the direction the exit road leads 120 m on (`headingFrom`, 8 compass points). The banner shows `wayOut` big and the street small below (`short`, `road` in `ui/NavView.tsx`); a roundabout as "2nd exit · towards Tullamore" (`ordinal` in `i18n`). Without signs it stays the street. Route fits keep 56 px round both ends for their markers (`ENDS_PX`), the overview measured from the banner and the bar.
- Heading while navigating: `NavState.moving` (hysteresis 3 → 1.5 m/s; progress counts only beyond GPS jitter, max(6 m, accuracy/2)) picks the route's course over the compass; standing still never flips it.
- Steps ahead: the banner always shows the step after the next (`then`, its distance from here beyond 150 m, the last one by the destination's name); its toggle opens `Steps` in `ui/TripDetails.tsx` (the same swipe panel as the ride's trip list, `tripList` in `App.tsx`, Back closes it), distances from `stepsAhead` in `core/navView.ts`.
- Guidance UI: `ui/NavBar.tsx` (time left, mute, End with a second tap; the voice is `useMuted` in `ui/voice.ts`: driving keeps it on or off for the next drive in `kosmos.muted.v1`, every other trip starts silent, as people are around; muted on foot or by bike, prompts buzz instead (`core/haptics.ts`: the alert once, the turn twice, arrival long; `vibrate` in `ui/native.ts`, `KosmosPlugin.vibrate` on Android, the browser's own elsewhere); Done on arrival, which also ends guidance after 60 s and closes the trip). `NavWaiting` (in `ui/NavView.tsx`) stands in whenever guidance has no route yet, so End is always on screen. Off the route the arrow and camera follow the fix itself. The app's own camera moves wait while a finger is on the map (`touching` in `App.tsx`): any move resets MapLibre's gesture handlers. Long-press does nothing while guiding. A failed reroute keeps the old route (`useRoute` reports `kept`), and the banner says so only while still off the route.
- Guidance is `core/nav.ts`: pure, fed fixes and time, covered by replay tests. Fixes worse than `COARSE_M` (65 m: network, tunnels, approximate) move the dot only; a turn is done only 10 m past it on the road after it (going straight on, or waiting at the light, takes no turn); off the route `prompt` stays quiet; going back down the route (40 m, or a course against it 3 fixes in a row) is off it; getting to the route from a car park is not. `ui/useGuidance.ts` wires it to the map: the arrow, the camera (both the user and the way back when off the route), rerouting that keeps the followed route until a new one arrives; the last fix counts at once at Start, and the dot follows while the route is still coming. Prompts are queued, never cut off (`ui/voice.ts`). A fix may only move along the route as far as plausible travel since the last one (`reachOf`), so self-crossing routes and U-turns onto the other carriageway skip nothing; arrival is said only on arriving and then latched; the early alert moves out with speed (30 s ahead). The UI only subscribes it to location (`useLocation().subscribe`) and renders `NavState`.
- Pins: `.pin`'s box ends at its tip (`styles/map.css`, anchor bottom), so it stands on the place at any zoom; an e2e test measures it.
- Sheets: `ui/Sheet.tsx` (place, route and results cards) minimise to a strip; a finger drags them from anywhere (`ui/useSwipe.ts`: 8 px, mostly vertical; a list under the finger scrolls until at its end; text fields and sideways moves are left alone; taps stay taps), a mouse from the grab bar. The ride's trip list folds away on a pull up the same way. The map buttons' column lets taps through between its buttons.
- Places from other apps: `core/shared.ts` (pure: `geo:`, OpenStreetMap, Google, Apple and OsmAnd links with a point, plain coordinates, else the message's words without its links, searched; Google's short links are never followed, as only Google can open them) and `ui/useShared.ts` (Android via `watchShared`, the web share target's `?title&text&url` and `?geo=`, cleared from the address bar; a point opens a card like a dropped pin, or by its name when one came along; logs only the kind).
- Layout: `ui/layout.ts` (the side layout for wide screens and phones held sideways, same query as `styles.css`; camera paddings; the column's width is `--side-w` in CSS and `sideWidth()` in JS, keep them equal), `ui/usePanel.ts` (publishes the panel height as `--panel-h` so the map buttons sit just above it; keeps a selected pin clear of its card; starts location on opening only when already granted), `ui/prefs.ts` (remembered choices), `ui/motion.ts` (camera moves honour reduced motion).
- Walking and cycling routes: `core/route.ts` sends Valhalla `walkway_factor` 0.6 and `sidewalk_factor` 0.8 (`FOOT_OPTIONS`): its defaults cost a four-lane road like a footpath. Bike routes send `use_roads` 0.25 (`BIKE_OPTIONS`, Valhalla's default 0.5): cycleways and quiet streets over busy roads. By car, when every way found has toll roads, one more request with `exclude_tolls` (`needsTollFree`, `withTollFree`) adds a way without, so there is always one to choose; Valhalla's `has_toll` (`Route.toll`) marks a way with coins on its tile and "Tolls" in the summary. Starting a toll-free way chosen over toll ones keeps its reroutes toll-free (`tollFree` in `App.tsx`, read by `useRoute` at request time, not part of its key). No toggle; `kosmos.tolls.v1` is retired.
- Units: `core/route.ts` `unitsFor` (region of the locale: US miles/feet, UK miles/yards, else metric) for display, speech, speed and the router's own instructions; `units` in `i18n`.
- Language: `i18n` picks en or de; `locale` is the browser's own tag for it (en-GB, de-AT) for clocks, weekdays, numbers and the voice. English copy is British. `capital` starts a sentence built from parts (lines without a name become "bus", "tram").
- Accessibility: `ui/a11y.ts` (a card's heading takes focus on opening, closing from the keyboard goes back to search; radio groups are one Tab stop with arrow keys). `.toasts` is the always-present live region, inside `.notes` with the offline note and "Search this area": one stack above the panel on phones, over the map beside the column in the side layout; a note without buttons lets taps through. The long-press hint is `ui/useHint.ts`. A button whose label names the next action has no `aria-pressed`; a toggle keeps one label with `aria-pressed` (mute). Colour tokens `--danger` and `--late` keep text contrast in both themes; targets are at least 44 px.
- Offline: the service worker keeps tiles under their URL without the planet build (`vite.config.ts`), so areas viewed once survive OpenFreeMap's weekly build. Playwright's routes still answer while the context is "offline": an offline test has to abort the requests itself.
- Styles: `src/styles.css` imports `src/styles/*.css` in cascade order (base: tokens, surfaces, search; map: place card, controls, credit, markers, About, notes; route: route card, public transport; navigation; layout: sheets, hover, motion, the side layout last).
- Keep each file under 800 lines; split before adding to it.

## Invariants

- Storage keys follow `kosmos.<name>.v<N>` (`kosmos.view.v1`). Never rename an existing key: bump the version and migrate.
- Network calls go only to OpenFreeMap, Photon, the FOSSGIS Valhalla router, Transitous and Nominatim (README → Privacy, CSP in `index.html`).
- Nominatim (`core/details.ts`, `ui/usePlaceDetails.ts`) follows the OSMF usage policy: one `lookup` by OSM id per place card opened, cached; as search fallback one `search` for a settled query only when Photon fails or exceeds 5 s, never as-you-type (a quick failure waits until the text has been left alone 5 s, or Enter; `SearchBar.tsx`); one request a second across both (`nominatimSlot` in `ui/http.ts`), which also names the app.
- Transitous (`core/transit.ts`) is volunteer-run too: one plan request per trip, travel-mode or departure change (the time field settles 800 ms first); one `stoptimes` request per stop card opened (`core/departures.ts`, around the stop's point, `ui/useDepartures.ts` keeps it a minute; a stop is a tapped `poi` label of a stop class or a Photon hit with a stop tag, `Place.stop`); while guiding, at most one `trip` check per ride (its vehicle's live times, platforms and cancellations at every stop), in the last 10 min before boarding and not within 3 min of planning (`ui/useRide.ts`). Never polled. Requests go through `ui/http.ts`. The Android app names itself with a User-Agent via `CapacitorHttp`; browsers send their Referer. `Mode` (road: Valhalla, turn-by-turn in `core/nav.ts`) vs `TravelMode` (adds `transit`: guided by `core/ride.ts`).
- The router is a volunteer service under fair use: one request per trip or travel-mode change (by car a second, without tolls, only when every way found has them), re-requested by an open road route only when the start moves more than 150 m (or twice the accuracy) and at most once a minute, never for public transport (`ui/useRoute.ts`), and while navigating only on a confirmed off-route, at most every 30 s and backing off to 4 min while standing in the same place (`rerouteDue` in `core/nav.ts`), for one route leaving in the direction of travel. Never poll it.
- A new data source or bundled asset goes into `THIRD_PARTY_NOTICES.md` (linked from About).
- No user-facing string is hard-coded. Add it to `src/i18n/en.ts` and `de.ts`.
- Android app ID `io.github.jibes.kosmos` and the release key are permanent; changing either breaks updates for installed users.

## Android

- `android/` is a committed Capacitor project; `npx cap sync android` copies `dist/` in (ignored by git).
- Icons are vector adaptive icons in `res/drawable` + `res/mipmap-anydpi`; web PNGs come from `npm run icons` (set `CHROMIUM_PATH` in cloud sessions).
- The app's own native code (registered in `MainActivity`): `KosmosPlugin.java` opens the app's system settings (offered when location was refused, `openAppSettings` in `ui/native.ts`) writes log lines under the tag `kOSMos` (`nativeLog`, `forwardErrors`) streams the ambient light while guiding (`light`, `watchLight` in `ui/native.ts`) buzzes turns (`vibrate`, accessibility usage so the system's vibration settings apply) and hands over places from other apps (`takeShared` for the one the app opened with, a retained `shared` event after; intent filters for `geo:`, openstreetmap.org links and shared text); `NavLocationPlugin.java` + `NavLocationService.java` keep location coming while guiding: a `location`-type foreground service on the platform's `LocationManager` (GPS and network, each asked whether switched on or not, and asked anew when location or a provider is switched on: Android 16 leaves a request made while location was off inactive), no Google Play services; it asks for location (on native the only prompt at Start: two at once cancel each other), once per run for precise where only approximate was given (and the app explains with a Settings button), and on Android 13+ for the notification once. `useLocation().background(true)` starts the WebView watch once the plugin has its answer and keeps it until the service's first fix. `KosmosPlugin.duck` holds navigation audio focus while prompts speak (other audio ducks); the status bar's icons follow the guidance theme (`SystemBars`).
- Release builds log nothing from the WebView (`loggingBehavior: 'debug'`): the bridge would otherwise write every fix to logcat. Too old a WebView (< 111, `minWebViewVersion`: the styles need `color-mix()`, `dvh`, `:has()`) shows `public/webview.html` (static, both languages, outside i18n since the app cannot run there).
- Back button: `ui/useBack.ts` (`@capacitor/app`) and Escape share one ladder in `App.tsx` (About → picker → navigation, which closes an open trip list first and then needs a second press → route → place → search); with nothing left back minimises the app instead of quitting.
- Navigation on Android: `useLocation().background(true)` moves location to `NavLocationService`; speech uses the system engine (`ui/voice.ts`), keep-awake the native plugin (`ui/wakeLock.ts`). The web build falls back to Web Speech and Screen Wake Lock.
- CI boots an Android 16 (API 36) emulator after the build and runs `scripts/android-smoke.sh` before any release: install without any permission granted, launch, no crash, no web errors, `kosmos:ready` logged under the tag `kOSMos` once the map loads; then guidance's location service (started as root, location switched off, then on): in the foreground, and `navigation: first fix` logged once `adb emu geo fix` arrives. The build job has no secrets (npm and Gradle run there, also for pull requests) and leaves the APK unsigned, with a throwaway-signed copy for the emulator; the `release` job (main only, `release` environment) first checks the version (already tagged: nothing to do; only a plain x.y.z newer than the last tag), then signs that tested APK with apksigner, checks the certificate against README and publishes. The Gradle wrapper JAR and distribution are checked against gradle.org's checksums. Its artifact `android-smoke` holds a screenshot with real tiles and the logcat; the latest screenshot is also force-pushed to the `ci-smoke` branch.
- Release: bump `package.json` version on main → `android.yml` publishes `v<version>` if that tag does not exist.

## Deviations

- `android.yml` uses the runner's preinstalled JDK 21 and Android SDK instead of setup actions, and boots the emulator with the SDK's own tools instead of `android-emulator-runner` (fewer third-party actions to pin).
- Fonts and tiles for scripts beyond Latin come from OpenFreeMap's glyph server at runtime; self-hosting all of Noto would add tens of MB.

## Done checklist (before every push)

1. `npm run check` (typecheck, lint, format:check, unit)
2. `npm run build && npm run e2e` (cloud sessions: `CHROMIUM_PATH=/opt/pw-browsers/chromium-*/chrome-linux/chrome` when the preinstalled Chromium does not match `@playwright/test`)
3. If you fixed a bug, a test now covers it.
4. README is updated if you changed behaviour, scripts or services.
